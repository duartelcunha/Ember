# Ember 1.3.1

Windows maintenance release for text refinement in the Codex desktop composer.

## What changed

- Ember can refine an explicit selection or the whole composer when Windows confirms that the
  focused Edit control, document and text are writable. An unsupported selection attribute no
  longer causes a false refusal when the document and value independently prove editability.
- Before automatic paste, Ember checks the same field, selection, original text and clipboard
  again. A detected change prevents replacement.
- For an explicitly selected, writable, non-password Edit control whose text range cannot be
  verified, Ember puts the result on the clipboard for manual paste. It does not select the
  whole field or send paste keys in this path.

## Installing

Back up `%APPDATA%\com.deleg8lab.ember\config.json`, then install over the existing copy with
`/UPDATE` (or `/S /UPDATE` for a silent upgrade). Do not run the old uninstaller first. Keep the
previous v1.3.0 installer and configuration backup until your own editors have been checked.
The updater signature authenticates the release artifact; there is no Windows Authenticode
publisher certificate, so SmartScreen may warn on first run.

## Known limits

Windows only. Protected, elevated and unverifiable fields are refused. A selected result in
an unsupported but verifiably writable Edit control requires manual paste. The exact native
application and environment evidence for this release is in
[native qualification](../native-qualification.md); this release does not claim automatic
replacement in every application.
